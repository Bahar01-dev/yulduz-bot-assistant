# CLAUDE.md — Навигация по проекту

## О проекте
Telegram-бот — персональный ИИ-агент для создания Instagram-контента в стиле владельца. Бот пишет посты и сценарии Reels на базе Claude claude-opus-4-8, работает только для одного пользователя, хранит профиль бренда и историю публикаций в SQLite. Репозиторий также содержит лендинг-портфолио (`/` — продакшн на Vercel), не связанный с ботом.

## 5 Ключевых решений

| # | Решение | Почему |
|---|---|---|
| 1 | **Один пользователь** | Нет авторизации, нет мультитенанси → простота. Бот блокирует всех кроме OWNER_TELEGRAM_ID |
| 2 | **SQLite, не PostgreSQL** | Один пользователь = нет конкурентных записей. Файл на Railway Persistent Volume. Zero config |
| 3 | **Три уровня памяти** | Постоянная (профиль) + долгосрочная (история) + сессионная (черновик). Без памяти бот пишет не в стиле владельца |
| 4 | **3 хука перед генерацией** | Пользователь выбирает угол подачи → бот генерирует только выбранное. Меньше итераций "переписать" |
| 5 | **aiogram FSM для состояний** | Онбординг — многошаговый диалог. FSM хранит шаг без глобальных переменных |

## Тестирование

**Где:** локально через `python main.py` + реальный Telegram-бот (тестовый токен)

**Чеклист перед деплоем:**
- [ ] Онбординг: `/start` → 5 шагов → профиль сохранён в БД
- [ ] Пост: свободный текст → 3 хука → выбор → полный пост + хэштеги + чеклист
- [ ] Reels: аналогично → сценарий с таймингами
- [ ] Кнопки: [Переписать] [Другой вар] [Сохранить] [В меню] — все работают
- [ ] Голос: `.ogg` от Telegram → расшифрован → обработан как текст
- [ ] Безопасность: чужой user_id → бот не отвечает
- [ ] Повторные темы: бот не дублирует темы из истории
- [ ] Railway: бот онлайн после рестарта контейнера, БД не потеряна

**Нет автотестов в MVP** — ручное QA по чеклисту достаточно для single-user бота.

## Переменные окружения

```env
TELEGRAM_BOT_TOKEN=       # @BotFather
ANTHROPIC_API_KEY=        # ключ провайдера: Anthropic (sk-ant-…) ИЛИ OpenRouter (sk-or-…)
LLM_BASE_URL=             # пусто → Anthropic; OpenRouter: https://openrouter.ai/api/v1
LLM_MODEL=                # пусто → дефолт; OpenRouter: anthropic/claude-opus-4
GROQ_API_KEY=             # console.groq.com (бесплатно) — голос, опционально
TAVILY_API_KEY=           # app.tavily.com (бесплатно) — тренды V2, опционально
OWNER_TELEGRAM_ID=        # @userinfobot
DATABASE_PATH=/app/data/bot.db
```

**LLM-провайдер:** слой генерации (`utils/errors.py`) поддерживает два пути — прямой
Anthropic SDK или OpenAI-совместимый шлюз (OpenRouter) при заданном `LLM_BASE_URL`.
Ключ в обоих случаях кладётся в `ANTHROPIC_API_KEY`.

**Опциональные ключи-гейты:** без `GROQ_API_KEY` выключен голос (`VOICE_ENABLED`),
без `TAVILY_API_KEY` выключены тренды (`TRENDS_ENABLED`) — раздел показывает подсказку
«добавь ключ». Обучение стилю и контент-план (V2) работают на одном `ANTHROPIC_API_KEY`.

## Механизм самообновления

При любом изменении — обновлять файлы в этом порядке:

```
1. spec.md    ← новая фича / изменение UX / новый агент / V2
2. CLAUDE.md  ← если изменилась структура папок, стек или ключевые решения
3. код        ← имплементация по обновлённой спеке
4. .env.example ← при добавлении нового API-ключа
```

**Правило:** CLAUDE.md описывает КАК устроено. spec.md описывает ЧТО делать.  
Если расходятся — истина в `spec.md`.

**Plan.md (трекинг разработки):** после завершения КАЖДОЙ фазы — обновить в `Plan.md`
сводную таблицу прогресса (статусы 📋→🚧→✅), колонку «Факт», блокеры, критерии готовности
и добавить запись в «Журнал изменений плана». Триггер продолжения работы: «Продолжи разработку по Plan.md».
