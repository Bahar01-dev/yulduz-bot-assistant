# Спецификация: ИИ-Агент для Instagram-блога
## Telegram-бот для создания контента в твоём стиле

**Версия:** 1.0  
**Дата:** 17 июня 2026  
**Статус:** Готово к разработке  
**Разработчик:** Claude Code (claude-opus-4-8)

---

## 1. Executive Summary

Telegram-бот — персональный ИИ-агент для ведения Instagram-блога в нише AI-инструментов, ботов и автоматизации для коучей, психологов и онлайн-школ. Работает только для одного пользователя (владельца). Задача: полностью убрать ручной труд по написанию постов и сценариев Reels. Бот пишет в стиле пользователя: пользователь  показывает примеры постов, которые ей нравятся, и бот подстраивается. и итеративно учится на обратной связи.

**Главная метрика успеха:** Готовый пост или сценарий Reels от первого запроса за < 60 секунд, без необходимости переписывать.

---

## 2. Проблема

Ведение Instagram-блога с нуля требует еженедельного производства контента:
- Написание постов: 1–3 часа на текст + хэштеги + структуру
- Сценарии Reels: ещё сложнее — нужны хук, тайминги, текст на экране, CTA
- Идеи для контента: непонятно о чём писать, что сейчас в тренде

Итог: контент либо не выходит, либо выходит редко и без системы. Бот решает всё три боли.

## 5. Архитектура системы памяти

Память — критическая часть. Без неё бот генерирует стандартный SMM-текст, а не твой стиль.

### 5.1 Три уровня памяти

```
┌─────────────────────────────────────────────────────┐
│ ПОСТОЯННАЯ ПАМЯТЬ (сохраняется навсегда)             │
│ • Профиль бренда (ниша, аудитория, тон, запреты)    │
│ • Референс-аккаунты                                  │
│ • Параметры стиля                                    │
└─────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────┐
│ ДОЛГОСРОЧНАЯ ПАМЯТЬ (накапливается)                  │
│ • История публикаций (что уже написали, темы)        │
│ • Сохранённые черновики (одобренный контент)         │
│ • Предпочтения по тону (что понравилось/нет) — V2   │
└─────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────┐
│ СЕССИОННАЯ ПАМЯТЬ (в рамках диалога)                 │
│ • Текущий черновик поста/сценария                    │
│ • Выбранный хук                                      │
│ • Состояние диалога (conversation state)             │
└─────────────────────────────────────────────────────┘
```

### 5.2 Модель данных (SQLite)

```sql
-- Профиль бренда пользователя
CREATE TABLE brand_profile (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER UNIQUE NOT NULL,
    niche TEXT NOT NULL,                    -- "AI-инструменты для коучей"
    target_audience TEXT NOT NULL,          -- "коучи, психологи, 30-50 лет"
    tone TEXT NOT NULL,                     -- "экспертный + дружеский"
    forbidden_words TEXT,                   -- через запятую
    reference_accounts TEXT,               -- "@account1, @account2"
    style_description TEXT,               -- краткое описание голоса
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- История опубликованных материалов
CREATE TABLE publications (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER NOT NULL,
    content_type TEXT NOT NULL,             -- 'post' | 'reel'
    topic TEXT NOT NULL,                    -- тема одной строкой
    content TEXT NOT NULL,                  -- финальный текст
    hooks TEXT,                             -- JSON: три варианта хуков
    selected_hook INTEGER,                  -- 1, 2 или 3
    saved_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Черновики (созданы но не отмечены как опубликованные)
CREATE TABLE drafts (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER NOT NULL,
    content_type TEXT NOT NULL,
    topic TEXT,
    content TEXT NOT NULL,
    hooks TEXT,                             -- JSON
    status TEXT DEFAULT 'draft',           -- 'draft' | 'approved'
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Настройки стиля (для V2: система обучения)
CREATE TABLE style_feedback (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER NOT NULL,
    content_snippet TEXT NOT NULL,
    verdict TEXT NOT NULL,                  -- 'approved' | 'rejected'
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 6. Мультиагентная архитектура

Бот построен на нескольких специализированных агентах. Каждый агент — это отдельный вызов Claude claude-opus-4-8 со своим системным промптом и контекстом из памяти.

```
Пользователь (Telegram)
        ↓
┌──────────────────┐
│   ОРКЕСТРАТОР    │  ← Python-логика: определяет тип запроса
│   (Router)       │     и маршрутизирует к нужному агенту
└────────┬─────────┘
         │
    ┌────┴────┐
    ↓         ↓
┌────────┐ ┌────────────┐
│ОНБОР-  │ │  КОНТЕНТ-  │
│ДИНГ    │ │  АГЕНТ     │ ← Claude claude-opus-4-8
│АГЕНТ   │ │            │   (post_writer / reel_writer)
│        │ │            │
└────────┘ └─────┬──────┘
                 ↓
         ┌───────────────┐
         │ МЕНЕДЖЕР      │  ← Python + SQLite
         │ ПАМЯТИ        │    (читает/пишет контекст)
         └───────────────┘
```

### 6.1 Оркестратор (Python Router)

Определяет намерение пользователя из свободного текста:

```python
INTENT_MAP = {
    "post":  ["напиши пост", "пост про", "сделай пост", "написать пост"],
    "reel":  ["рилс", "reels", "сценарий", "видео про", "сделай рилс"],
    "plan":  ["контент-план", "план на", "планирование"],        # V2
    "trend": ["тренды", "что популярно", "конкуренты", "анализ"] # V2
}
```

Если намерение не определено → вежливо уточнить: "Напиши пост, сценарий Reels или что-то другое?"

### 6.2 Контент-агент — Системный промпт

Каждый вызов контент-агента включает:

```
SYSTEM PROMPT:
═══════════════════════════════════════════════════
Ты — персональный контент-менеджер и копирайтер.

ПРОФИЛЬ БРЕНДА:
Ниша: {niche}
Аудитория: {target_audience}
Тон: {tone}
Запрещённые слова/фразы: {forbidden_words}
Стиль-ориентир: {style_description}

ИСТОРИЯ: Уже написаны посты на темы: {recent_topics_list}
Избегай повторения этих тем и формулировок.

ПРАВИЛА ГЕНЕРАЦИИ:
- Пиши как живой эксперт, не как ChatGPT
- Никакого "В заключение", "Таким образом", "Безусловно"
- Конкретные цифры и примеры вместо общих слов
- Разговорный стиль, но с экспертной глубиной
- Хук — первые 1-2 строки — должны останавливать скролл

{format_instructions}  ← зависит от типа запроса
═══════════════════════════════════════════════════
```

### 6.3 Агент онбординга

Отдельный промпт для первичного сбора профиля бренда. Запускается только один раз (при `/start`) если профиль не существует.

## 7. Пользовательские сценарии (User Journeys)

### 7.1 Онбординг (первый запуск)

```
Пользователь → /start

Бот → "Привет! Я твой ИИ-агент для Instagram. Прежде чем писать —
       давай настрою твой голос. 5 коротких вопросов. Начинаем?"
       [Поехали →]

Шаг 1: "Как называется твоя ниша? 
        Например: 'AI-инструменты для коучей и психологов'"
        → Пользователь отвечает текстом

Шаг 2: "Кто твоя аудитория?
        Возраст, профессия, их главная боль одной фразой."
        → Пользователь отвечает текстом

Шаг 3: "Как ты хочешь звучать в блоге? (можно выбрать несколько)"
        [Экспертный] [Дружеский] [Прямой] [С юмором] [Провокационный]

Шаг 4: "Есть слова или фразы, которые тебе не нравятся?
        Например: 'синергия', 'эффективно', 'успех' (или пропусти)"
        [Пропустить] → Пользователь отвечает текстом или пропускает

Шаг 5: "Назови 1-3 Instagram аккаунта, чей стиль тебе нравится.
        @ или ссылка — неважно. Я возьму их как ориентир."
        → Пользователь вводит аккаунты

Бот → "Профиль сохранён ✓

Ниша: {niche}
Аудитория: {audience}
Тон: {tone}
Ориентиры: {accounts}

Можем начинать. Напиши: 'пост про [тема]' или 'рилс про [тема]'"
```

Бот →

Я тестировал ChatGPT как коуча целую неделю. Вот что вышло

### 7.3 Сценарий Reels

```
Пользователь: "рилс про то что боты экономят коучу 10 часов в неделю"

Бот → typing...

Бот →
🎬 *ТРИ ВАРИАНТА ХУКА* (первые 3 секунды):

*1.* "Ты тратишь 10 часов в неделю на то, что бот делает за 5 минут..."
*2.* "Я верну тебе 10 часов в неделю. Вот как именно"
*3.* "Покажу что я перестал делать руками как разработчик ботов"

[Хук 1] [Хук 2] [Хук 3]

↓ Пользователь выбирает [Хук 1]

Бот →

📺 На экране: список задач которые зачёркиваются

📺 На экране: скриншот — клиент пишет → бот отвечает мгновенно
🎬 Визуал: телефон в руке, чат с ботом

━━━ CTA (25–30 сек) ━━━
🎙 Голос: "Напиши в комментарии БОТ — пришлю как это работает"
📺 На экране: "Пиши БОТ ↓"
🎬 Визуал: прямой взгляд в камеру

---
📝 *ПОДПИСЬ ДЛЯ REELS:*
[готовый текст...]

#️⃣ *ХЭШТЕГИ:*
#telegram #бот #автоматизация #коуч #ии

---
[Переписать] [Другой хук] [Изменить длину] [Сохранить] [В меню]
```

### 8.1 Основной стек

### 9.3 Чеклист перед публикацией

Автоматически генерируется для каждого поста и сценария:

```
✅ Чеклист перед публикацией:
✓ Хук останавливает скролл в первые 2 строки
✓ Есть конкретика (цифры / пример / история)
✓ CTA понятен и один (не два разных)
✓ Длина поста: оптимально / короткий / длинный
✓ Хэштеги отделены от текста
```

Если что-то не соответствует — показать ⚠️ и объяснить что исправить.

## 11. Правила безопасности и доступа

Бот работает только для одного авторизованного пользователя.

```python
# В каждом handler:
OWNER_TELEGRAM_ID = int(os.getenv("OWNER_TELEGRAM_ID"))

async def is_owner(user_id: int) -> bool:
    return user_id == OWNER_TELEGRAM_ID

# Если кто-то другой пишет боту:
# → "Этот бот работает только для своего владельца."
# → Прекратить обработку
```

`OWNER_TELEGRAM_ID` хранится в переменных окружения Railway.

## 12. Деплой — Railway.app

### Шаги деплоя:

1. Создать репозиторий на GitHub
2. Подключить к Railway (railway.app → New Project → Deploy from GitHub)
3. Добавить переменные окружения в Railway Dashboard:
   ```
   TELEGRAM_BOT_TOKEN=...
   ANTHROPIC_API_KEY=...
   GROQ_API_KEY=...
   OWNER_TELEGRAM_ID=...
   DATABASE_PATH=/app/data/bot.db
   ```
4. Railway автоматически запускает бот через Dockerfile

### Dockerfile

```dockerfile
FROM python:3.12-slim

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# Persistent volume для SQLite базы данных
VOLUME ["/app/data"]

CMD ["python", "main.py"]
```

### Persistent Volume (SQLite)

В Railway: Settings → Volumes → Mount at `/app/data`  
Это обеспечивает сохранность базы данных при перезапусках.

## 13. Промпт-стратегия

### 13.1 Принципы промптинга

- Профиль бренда передаётся в **каждый** системный промпт целиком
- История последних 10 публикаций передаётся как контекст (для дедупликации тем)
- Формат вывода задаётся жёстко в промпте (бот не должен придумывать структуру)
- Temperature: 0.7 для постов, 0.8 для Reels (немного больше креативности)

### 13.2 Дедупликация тем

Перед генерацией — Memory Manager проверяет: есть ли похожая тема в истории.

```python
recent_topics = db.get_recent_topics(limit=20)
# Передаётся в промпт: "Уже написаны посты на темы: {list}"
# Клод сам избегает повторений
```

### 13.3 Обучение стилю (V2)

Кнопка [Одобрить] → сохраняет фрагмент в `style_feedback` с вердиктом "approved"  
Кнопка [Отклонить] → сохраняет с "rejected"  
Накопленные примеры добавляются в системный промпт: "Примеры ХОРОШЕГО стиля: ... Примеры ПЛОХОГО стиля: ..."

## 14. Обработка ошибок

| Ситуация | Поведение бота |
|---|---|
| Claude API не отвечает | "Попробую ещё раз через секунду..." → retry x2 → "Сервис временно недоступен. Попробуй через минуту." |
| Groq Whisper недоступен | "Голосовой ввод временно недоступен. Напиши текстом." |
| Онбординг не завершён | "Нужно настроить профиль сначала. /start чтобы начать." |
| Пустой профиль бренда | Не генерировать контент, вернуть в онбординг |
| Слишком длинный запрос | Принять, не обрезать (Claude справится) |
