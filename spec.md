# Спецификация: ИИ-Агент для Instagram-блога
## Telegram-бот для создания контента в твоём стиле

**Версия:** 1.0  
**Дата:** 17 июня 2026  
**Статус:** Готово к разработке  
**Разработчик:** Claude Code (claude-opus-4-8)

---

## 1. Executive Summary

Telegram-бот — персональный ИИ-агент для ведения Instagram-блога в нише AI-инструментов, ботов и автоматизации для коучей, психологов и онлайн-школ. Работает только для одного пользователя (владельца). Задача: полностью убрать ручной труд по написанию постов и сценариев Reels. Бот пишет в стиле пользователя: пользователь  показывает примеры постов, которые ей нравятся, и бот подстраивается. и итеративно учится на обратной связи.

**Главная метрика успеха:** Готовый пост или сценарий Reels от первого запроса за < 60 секунд, без необходимости переписывать.

---

## 2. Проблема

Ведение Instagram-блога с нуля требует еженедельного производства контента:
- Написание постов: 1–3 часа на текст + хэштеги + структуру
- Сценарии Reels: ещё сложнее — нужны хук, тайминги, текст на экране, CTA
- Идеи для контента: непонятно о чём писать, что сейчас в тренде

Итог: контент либо не выходит, либо выходит редко и без системы. Бот решает всё три боли.

## 5. Архитектура системы памяти

Память — критическая часть. Без неё бот генерирует стандартный SMM-текст, а не твой стиль.

### 5.1 Три уровня памяти

```
┌─────────────────────────────────────────────────────┐
│ ПОСТОЯННАЯ ПАМЯТЬ (сохраняется навсегда)             │
│ • Профиль бренда (ниша, аудитория, тон, запреты)    │
│ • Референс-аккаунты                                  │
│ • Параметры стиля                                    │
└─────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────┐
│ ДОЛГОСРОЧНАЯ ПАМЯТЬ (накапливается)                  │
│ • История публикаций (что уже написали, темы)        │
│ • Сохранённые черновики (одобренный контент)         │
│ • Предпочтения по тону (что понравилось/нет) — V2   │
└─────────────────────────────────────────────────────┘
         ↓
┌─────────────────────────────────────────────────────┐
│ СЕССИОННАЯ ПАМЯТЬ (в рамках диалога)                 │
│ • Текущий черновик поста/сценария                    │
│ • Выбранный хук                                      │
│ • Состояние диалога (conversation state)             │
└─────────────────────────────────────────────────────┘
```

### 5.2 Модель данных (SQLite)

```sql
-- Профиль бренда пользователя
CREATE TABLE brand_profile (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER UNIQUE NOT NULL,
    niche TEXT NOT NULL,                    -- "AI-инструменты для коучей"
    target_audience TEXT NOT NULL,          -- "коучи, психологи, 30-50 лет"
    tone TEXT NOT NULL,                     -- "экспертный + дружеский"
    forbidden_words TEXT,                   -- через запятую
    reference_accounts TEXT,               -- "@account1, @account2"
    style_description TEXT,               -- краткое описание голоса
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- История опубликованных материалов
CREATE TABLE publications (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER NOT NULL,
    content_type TEXT NOT NULL,             -- 'post' | 'reel'
    topic TEXT NOT NULL,                    -- тема одной строкой
    content TEXT NOT NULL,                  -- финальный текст
    hooks TEXT,                             -- JSON: три варианта хуков
    selected_hook INTEGER,                  -- 1, 2 или 3
    saved_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Черновики (созданы но не отмечены как опубликованные)
CREATE TABLE drafts (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER NOT NULL,
    content_type TEXT NOT NULL,
    topic TEXT,
    content TEXT NOT NULL,
    hooks TEXT,                             -- JSON
    status TEXT DEFAULT 'draft',           -- 'draft' | 'approved'
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Настройки стиля (для V2: система обучения)
CREATE TABLE style_feedback (
    id INTEGER PRIMARY KEY,
    user_telegram_id INTEGER NOT NULL,
    content_snippet TEXT NOT NULL,
    verdict TEXT NOT NULL,                  -- 'approved' | 'rejected'
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Кэш трендового брифа за день (V2.1: тренды по расписанию + факты в постах, §20)
CREATE TABLE trend_brief (
    brief_date TEXT PRIMARY KEY,            -- 'YYYY-MM-DD', одна строка на день
    raw_search TEXT NOT NULL,               -- сырые результаты Tavily = grounding для постов
    topics_json TEXT NOT NULL,              -- JSON-список тем брифа (текст тем)
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 6. Мультиагентная архитектура

Бот построен на нескольких специализированных агентах. Каждый агент — это отдельный вызов Claude claude-opus-4-8 со своим системным промптом и контекстом из памяти.

```
Пользователь (Telegram)
        ↓
┌──────────────────┐
│   ОРКЕСТРАТОР    │  ← Python-логика: определяет тип запроса
│   (Router)       │     и маршрутизирует к нужному агенту
└────────┬─────────┘
         │
    ┌────┴────┐
    ↓         ↓
┌────────┐ ┌────────────┐
│ОНБОР-  │ │  КОНТЕНТ-  │
│ДИНГ    │ │  АГЕНТ     │ ← Claude claude-opus-4-8
│АГЕНТ   │ │            │   (post_writer / reel_writer)
│        │ │            │
└────────┘ └─────┬──────┘
                 ↓
         ┌───────────────┐
         │ МЕНЕДЖЕР      │  ← Python + SQLite
         │ ПАМЯТИ        │    (читает/пишет контекст)
         └───────────────┘
```

### 6.1 Оркестратор (Python Router)

Определяет намерение пользователя из свободного текста:

```python
INTENT_MAP = {
    "post":  ["напиши пост", "пост про", "сделай пост", "написать пост"],
    "reel":  ["рилс", "reels", "сценарий", "видео про", "сделай рилс"],
    "plan":  ["контент-план", "план на", "планирование"],        # V2 ✅ реализовано
    "trend": ["тренды", "что популярно", "конкуренты", "анализ"] # V2 ✅ (нужен TAVILY_API_KEY)
}
```

> **V2 реализовано (Фаза 11):** intent `plan` → поток контент-плана (`handlers/plan.py`),
> intent `trend` → анализ трендов через Tavily (`handlers/trends.py`, гейт по `TAVILY_API_KEY`).

Если намерение не определено → вежливо уточнить: "Напиши пост, сценарий Reels или что-то другое?"

### 6.2 Контент-агент — Системный промпт

Каждый вызов контент-агента включает:

```
SYSTEM PROMPT:
═══════════════════════════════════════════════════
Ты — персональный контент-менеджер и копирайтер.

ПРОФИЛЬ БРЕНДА:
Ниша: {niche}
Аудитория: {target_audience}
Тон: {tone}
Запрещённые слова/фразы: {forbidden_words}
Стиль-ориентир: {style_description}

ИСТОРИЯ: Уже написаны посты на темы: {recent_topics_list}
Избегай повторения этих тем и формулировок.

ПРАВИЛА ГЕНЕРАЦИИ:
- Пиши как живой эксперт, не как ChatGPT
- Никакого "В заключение", "Таким образом", "Безусловно"
- Конкретные цифры и примеры вместо общих слов
- Разговорный стиль, но с экспертной глубиной
- Хук — первые 1-2 строки — должны останавливать скролл

{format_instructions}  ← зависит от типа запроса
═══════════════════════════════════════════════════
```

### 6.3 Агент онбординга

Отдельный промпт для первичного сбора профиля бренда. Запускается только один раз (при `/start`) если профиль не существует.

## 7. Пользовательские сценарии (User Journeys)

### 7.1 Онбординг (первый запуск)

```
Пользователь → /start

Бот → "Привет! Я твой ИИ-агент для Instagram. Прежде чем писать —
       давай настрою твой голос. 5 коротких вопросов. Начинаем?"
       [Поехали →]

Шаг 1: "Как называется твоя ниша? 
        Например: 'AI-инструменты для коучей и психологов'"
        → Пользователь отвечает текстом

Шаг 2: "Кто твоя аудитория?
        Возраст, профессия, их главная боль одной фразой."
        → Пользователь отвечает текстом

Шаг 3: "Как ты хочешь звучать в блоге? (можно выбрать несколько)"
        [Экспертный] [Дружеский] [Прямой] [С юмором] [Провокационный]

Шаг 4: "Есть слова или фразы, которые тебе не нравятся?
        Например: 'синергия', 'эффективно', 'успех' (или пропусти)"
        [Пропустить] → Пользователь отвечает текстом или пропускает

Шаг 5: "Назови 1-3 Instagram аккаунта, чей стиль тебе нравится.
        @ или ссылка — неважно. Я возьму их как ориентир."
        → Пользователь вводит аккаунты

Бот → "Профиль сохранён ✓

Ниша: {niche}
Аудитория: {audience}
Тон: {tone}
Ориентиры: {accounts}

Можем начинать. Напиши: 'пост про [тема]' или 'рилс про [тема]'"
```

## 8. Технический стек

### 8.1 Основной стек

| Компонент | Технология | Обоснование |
|---|---|---|
| Язык | Python 3.12 | Стандарт для Telegram-ботов и AI |

| Веб-поиск (V2) | Tavily API | AI-оптимизированный поиск |

### 8.2 Необходимые API-ключи

| Ключ | Где получить | Нужен для |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather | Бот в Telegram |
| `ANTHROPIC_API_KEY` | console.anthropic.com | Генерация контента (Claude) |
| `GROQ_API_KEY` | console.groq.com | Голосовой ввод (Whisper) |
| `TAVILY_API_KEY` | app.tavily.com | Тренды и конкуренты (V2) |

> Все ключи хранятся в переменных окружения Railway, НИКОГДА не в коде.

## 13. Промпт-стратегия

### 13.1 Принципы промптинга

- Профиль бренда передаётся в **каждый** системный промпт целиком
- История последних 10 публикаций передаётся как контекст (для дедупликации тем)
- Формат вывода задаётся жёстко в промпте (бот не должен придумывать структуру)
- Temperature: 0.7 для постов, 0.8 для Reels (немного больше креативности)

### 13.2 Дедупликация тем

Перед генерацией — Memory Manager проверяет: есть ли похожая тема в истории.

```python
recent_topics = db.get_recent_topics(limit=20)
# Передаётся в промпт: "Уже написаны посты на темы: {list}"
# Клод сам избегает повторений
```

### 13.3 Обучение стилю (V2)

Кнопка [Одобрить] → сохраняет фрагмент в `style_feedback` с вердиктом "approved"  
Кнопка [Отклонить] → сохраняет с "rejected"  
Накопленные примеры добавляются в системный промпт: "Примеры ХОРОШЕГО стиля: ... Примеры ПЛОХОГО стиля: ..."

### 13.4 Grounding: реальные факты вместо выдумки (V2.1)

`build_system_prompt(...)` получает необязательный аргумент `grounding: str | None`.
Если задан — в системный промпт добавляется блок «СВЕЖИЕ ФАКТЫ ИЗ ИНТЕРНЕТА (на сегодня)»
с сырыми результатами поиска и правилом «опирайся на эти факты; НЕ выдумывай того,
чего здесь нет — иначе пиши обобщённо, без вымышленных цифр». Если `grounding=None`
— промпт остаётся как в V2 (обратная совместимость). Подробнее — §20.

## 20. V2.1 — Трендовый бриф по расписанию + факты (grounding) в постах

**Статус:** спроектировано (2026-07-05), готово к плану реализации.

### 20.1 Проблема

Написание поста не ходит в интернет: пост опирается только на профиль, историю и знания
модели → «придумывает данные от ума», факты и цифры устаревшие/выдуманные. Веб-поиск
(Tavily) есть, но живёт отдельной командой `/тренды` и не участвует в написании поста.
В быстро меняющейся нише (вайбкодинг: сайты, боты, ассистенты, контент-помощники на AI)
это критично.

**Цель:** бот сам, по расписанию, находит свежие тренды ниши и присылает темы постов;
выбранная тема одним тапом превращается в пост/Reels, **опирающийся на реальные факты из
того же поиска**, а не на выдумку.

### 20.2 Зафиксированные решения

- Ниша остаётся (вайбкодинг/AI); проблема не в теме, а в актуальности.
- Основной сценарий — бот сам находит тренды и предлагает темы (проактивно).
- Доставка — по расписанию: утренний бриф раз в день.
- Источник — Tavily (веб-поиск): работает сразу, легально. Instagram-аккаунт — отдельной
  фичей позже (см. §20.9).
- Время/пояс: `09:00`, `Asia/Almaty` (UTC+5) — дефолты, настраиваются через env.

### 20.3 Поток данных

```
[APScheduler, раз в день в HH:MM TZ]      [/тренды — вручную, в любой момент]
                │                                      │
                └──────────────┬───────────────────────┘
                               ▼
                   fetch_trends(profile)  → Tavily-поиск (safe_search)
                               │  raw_search
                               ▼
                   build_brief(raw_search, profile) → Claude: 2-3 тренда + 3-5 тем
                               │            (safe_generate)
                    сохраняем в trend_brief (кэш за день)
                               ▼
                   bot.send_message(владельцу):
                   бриф + кнопки [Тема 1]…[Тема N] [🔁 Обновить]
                               │
             тап по теме ──────┘
                               ▼
             generate_hooks(тема, grounding=raw_search) → 3 хука →
             (выбор) → generate_post(хук, grounding=raw_search)
                               ▼
                 пост с РЕАЛЬНЫМИ фактами, не выдумка
```

**Принцип:** «поиск фактов» и «написание поста» — отдельные кирпичики. Grounding хранится
за днём: тап по теме в обед берёт утренний кэш (повтор поиска не нужен), факты в хуках и
посте согласованы.

### 20.4 Компоненты

- **Grounding** (§13.4): `build_system_prompt` + `generate_hooks`/`generate_post` получают
  необязательный `grounding`; аддитивно, без grounding — поведение V2.
- **Трендовый сервис:** `fetch_trends(profile)` (Tavily через `safe_search`) и
  `build_brief(raw, profile)` (Claude через `safe_generate`, парсимый список тем). В
  `agents/trend_analyst.py` (расширение) — зовут и планировщик, и `/тренды`.
- **Формат брифа:** `prompts/trend_prompt.py` выводит темы жёстко парсимым списком
  (`ТЕМА_1: …`, по образцу `HOOK_N`); парсер тем — по образцу `parse_hooks()`.
- **Планировщик:** `APScheduler` (`AsyncIOScheduler`) стартует в `main.py`, одна
  ежедневная cron-задача (`hour/minute`, `timezone`). Задача в try/except (сбой не роняет
  планировщик); стартует только при `TRENDS_ENABLED`. Новый модуль `utils/scheduler.py`.
- **Хранение:** таблица `trend_brief` (§5.2), модуль `database/trend_brief.py`; `🔁 Обновить`
  = upsert строки за сегодня.
- **UI/callbacks:** `utils/keyboards.py` — клавиатура брифа; `callback_data` =
  `trendtopic:<brief_date>:<index>` (обход лимита 64 байта, текст темы и grounding — из БД).
  `handlers/callbacks.py` — обработчики `trendtopic:*` и `🔁 Обновить`. `handlers/trends.py` —
  `/тренды` строит тот же бриф с той же клавиатурой.
- **Конфиг:** `TREND_DIGEST_TIME=09:00`, `TREND_TZ=Asia/Almaty` (дефолты); `apscheduler`
  в `requirements.txt`; переменные — в `.env.example`.

### 20.5 Затрагиваемые файлы

**Новые:** `utils/scheduler.py`, `database/trend_brief.py`.
**Изменяются:** `prompts/style_builder.py`, `agents/post_writer.py`, `agents/trend_analyst.py`,
`prompts/trend_prompt.py`, `handlers/trends.py`, `handlers/callbacks.py`, `utils/keyboards.py`,
`config.py`, `main.py`, `requirements.txt`, `.env.example`, `database/db.py` (создание
таблицы `trend_brief`).

### 20.6 Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет `TAVILY_API_KEY` | Планировщик не стартует; `/тренды` показывает подсказку «добавь ключ». Без падений. |
| Tavily сбоил/пусто в утренней задаче | try/except + лог; владельцу «сегодня тренды подтянуть не удалось, попробуй `/тренды` позже». |
| LLM сбоил при сборке брифа | `safe_generate` вернёт дружелюбное сообщение; бриф не сохраняем. |
| Тап по теме, кэш пропал/устарел | «бриф устарел, нажми 🔁 Обновить» → свежий поиск пересобирает бриф. |
| Тап по вчерашней кнопке | `callback_data` несёт дату; дата ≠ сегодня → предлагаем обновить. |
| Рестарт бота | Планировщик заново регистрирует задачу из env; кэш в БД (Persistent Volume) цел. |
| Пустой профиль | `build_search_query` → общий запрос (как сейчас). |
| Мало/шумные результаты Tavily | Правило «не выдумывай» → пост менее конкретный, но без выдуманных цифр. |

### 20.7 Критерии готовности

- [ ] С `TAVILY_API_KEY` в 09:00 (Asia/Almaty) бот сам присылает бриф: 2-3 тренда + 3-5 тем кнопками.
- [ ] Тап по теме → 3 хука → выбор → пост, где факты/названия/цифры взяты из поиска.
- [ ] `🔁 Обновить` пересобирает бриф за сегодня свежим поиском.
- [ ] `/тренды` вручную выдаёт тот же бриф с теми же кнопками.
- [ ] Без ключа бот не падает; `/тренды` показывает подсказку, планировщик не стартует.
- [ ] Рестарт: расписание восстанавливается, вчерашний кэш в БД цел.
- [ ] Обычный пост без grounding работает как в V2 (регрессий нет).

### 20.8 Обоснование ключевых решений

| Решение | Почему |
|---|---|
| Grounding как отдельный опциональный кирпичик | Работает в расписании и (позже) в ручном написании; не ломает V1/V2. |
| Кэш брифа за день в БД | Тап не гоняет Tavily повторно; факты согласованы; переживает рестарт. |
| APScheduler в процессе бота | Бот и так крутится 24/7 (long-polling); отдельный сервис/cron не нужен. |
| Время/пояс через env | Просто; смена = одна переменная на Railway. In-bot настройка — позже. |
| `callback_data` = дата+индекс | Обход лимита 64 байта; текст темы и grounding — из БД. |

### 20.9 Осознанно вне области (YAGNI / позже)

- **Instagram/YouTube через API** — официальный Graph API даёт в основном свою статистику
  + хэштег-поиск (нужен бизнес-аккаунт и ревью Meta); неофициальный вход под логином
  нарушает правила и рискует блокировкой аккаунта. Отложено в отдельную фичу (аналитика
  своих постов + хэштег-поиск), ближе к V3.
- **Дедупликация трендов**, несколько под-запросов, учёт источников — если начнёт повторяться.
- **Настройка расписания кнопками в боте** — позже; в V1 через env.
- **Grounding для Reels и для ручного написания поста** — механизм готов, включение —
  следующим шагом.
